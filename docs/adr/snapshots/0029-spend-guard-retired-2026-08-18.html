Retiring the Spend Guard

Architecture Decision Record 0029 Accepted Executed by deletion

The in-band spend guard is retired

A failed experiment, and what it cost to learn that. Five weeks, zero prevented spend, two self-inflicted fail-opens — and a charter that had already said not to build it.

The in-band, pre-execution, text-matching spend guard was the wrong shape, and it was wrong for a structural reason rather than a quality one. No amount of further work converges it. It is retired rather than fixed.

This is written as a failed experiment on purpose. The framework's stated product is findings, not automation. A mechanism that ran for five weeks and produced no prevention but several sharp lessons is exactly that — provided the lessons are recorded before the code goes.

01What it was

Three layers, each in a different trust domain. The taxonomy was right and survives this decision. Only layer 1 is retired.

02What worked

Recorded because it is the part worth carrying forward. Whoever builds the replacement wants this, not a summary of it.

✓ 01

Reading one level into invoked scripts caught a genuine hole. conclave's sweep-gpu-capacity.sh runs a provisioning command on line 23; a name-only classifier waves it straight through. The generalisable form: a classifier that reads the command but not what the command runs is checking the wrong text.

✓ 02

The invariant: a spend gate must never be able to block the exit. Spec 06 as first written hard-stopped by rejecting further Bash on overrun — which would freeze an agent holding a live GPU and block its own teardown, causing the runaway it existed to prevent. Any replacement must preserve this.

✓ 03

The disposition-verb axis. What does the detector's over-firing mean? Where over-firing is designed in, the model filtering it is the architecture; where it is a defect, a model-emitted exit is that defect's own bypass. That reasoning is general, was reused four weeks later for a different predicate, and survives entirely.

✓ 04

A test must never become evidence about the thing it tests. Twice: 26 manufactured denial events, then 31 manufactured dismissals. The second is sharper — the containment set an environment variable nothing reads, so it ran and reached nobody.

✓ 05

Auditing it found real defects in it. The grant verb was agent-callable behind nothing but a sentence; five plain-literal bypasses; a counter sitting at 47 against a cap of 3. Genuine finds. But note what that sentence actually says: the measured value of this mechanism is that inspecting it produced bugs in itself. That is not the thing it was built for.

03What did not work

The substance of the verdict.

✗ 01

It never prevented a real unauthorized spend. Not once, in five weeks. Every denial for which evidence exists was a false positive. The three real holes it is credited with were all found by inspection while testing or auditing it — never by it firing in anger.

✗ 02

It is a classifier over an unbounded input space that must be correct at the token level. The preceding ADR had already conceded this for one sub-case — "the launcher set is every exec-wrapper on the system; it cannot be enumerated." That generalises to quoting, escaping, heredocs, runtime assembly and cloud SDKs. Shell parsing inside a safety control is a hard problem being solved with regexes, and the edge cases do not run out.

✗ 03

Three review rounds in one day produced two block→allow regressions — both in fixes for a false positive, both invisible to a fully green suite, both found only by an independent reviewer diffing classifications against the original. The last was an ordinary apostrophe turning a real boot into an allowed teardown:

echo don't run terraform destroy || terraform apply
  →  classified "reducing"  →  ALLOWED UNCONDITIONALLY
✗ 04

Its false positives land almost entirely on the people maintaining it. Five in one session, a 100% false-positive rate, every one produced by working on or verifying the guard — including two hit by the independent reviewer, the mechanism the charter rates highest. A control whose friction falls mainly on its own auditors is obstructing its own verification. With Claude specifically this is not fixable: an agent that writes documentation, tests and decision records about infrastructure will trip a text classifier aimed at infrastructure.

✗ 05

It failed OPEN in the way that matters. On a /usr/bin-first PATH it did not parse, exited 1, and the wrapper passed that through as ALLOW. The guard was itself the vulnerability.

✗ 06

Its backstop shipped disabled to every clone, silently, for weeks — a global counter at 47 against a cap of 3.

✗ 07

It needed a detector, which needed a detector. Guard → backstop (does the agent obey the denial's prose?) → P15 (is the backstop still alive?). Three layers of watching for a control that has never fired in anger, each with its own noise and its own failure modes.

✗ 08

It contradicted the framework's own charter, and nobody re-examined it. ADR-0006 retargeted Tessera to instrumentation, not control, ranked "make the bad state unrepresentable" tier 1 and out-of-band bounds tier 2, put text-matching at tier 4, and warned that every in-band mechanism is subject to the same silent failure as the agent it guards. The spend guard is a pre-execution deny gate — control, in-band, tier 4 — and it went on being the flagship safety mechanism for five weeks after the charter said to stop building exactly that. Every failure above is one that charter predicted in the abstract.

Layer 1 is a precondition for unsupervised operation, and unsupervised operation never happened.

The deeper mistake, stated once

The autonomy roadmap was demoted from goal to hypothesis; the readiness claim was never restored. So the mechanism was built, maintained, debugged and defended for a condition that has not arrived — while imposing real cost every week on the condition that had.

Build the control when the run that needs it is real, and build it at the tier the charter already names.

04What replaces it

Nothing, here. Tessera's job under the charter is "to ensure they exist, not to be them."

  • Tier 1, in conclave — remove the capability. An agent without provisioning credentials cannot boot a GPU: not denied, impossible. The envelope becomes a scoped credential with a TTL issued by a human, rather than permission to pass a regex. Nearly identical to the existing command; entirely different enforcement; no parsing and no false positives.
  • Tier 2, detection — observe effects, not commands. A GPU either exists or it does not: a bounded, enumerable space, unlike the set of strings that might create one. CloudTrail plus the existing budget hardstop already covers it.

Neither is built by this decision, and that is a real gap stated rather than implied. Between the unwind and conclave adopting scoped credentials there is no per-run authorization layer at all. The honest weighing is that layer 1's measured prevention is zero, so what is lost is nominal coverage rather than actual — but a reader in six months should not have to infer that.

05How this record verifies itself

The Executed: field is machine-checked: every path it names under removed: must be absent from disk, and the check reports if a cut was recorded rather than made. That verification was silently doing nothing here.

The value originally wrapped across four lines. The parser matches a single line, so it saw only the first two paths — the removal claims for both hook shims were verified by nothing at all. Restore either file and the check stays green, in the record whose subject is honest execution accounting.

Reflowing it naively would have been worse. Everything after removed: reads as removed, and the continuation named six paths that were deliberately kept — so the one-line version would have gone red demanding their deletion. The fix is a one-line removed: plus a separate "also changed" field, which is why the record above has two fields where it had one.

06Consequences

  • Nominal safety coverage is reduced; measured coverage is unchanged. Say it in that order.
  • The chaos suite drops from 11 probes to 7. Probes 1–4 used spend as their vehicle: 1–3 the guard, 4 the backstop. Probe 3's coverage survives in the doc-checker's Python 3.9 probe; probe 4's in probe 8, which is generic. Probes 1 and 2 are genuinely retired with their subject.

    Corrected before this landed. The first draft of this bullet read "11 probes to 9 (probes 1 and 2)". Both numbers were wrong, and contradicted the record's own Executed: line and the measured result — in the decision record whose subject is honest accounting. Caught by an independent reviewer, not by any check. Sharper still: this published copy carried the correct figure while the source file carried the wrong one — the drift this snapshot was flagged for, arriving within hours and pointing the other way.

  • P15 goes with it, removing one of the graduation predicate's remaining legs.
  • The disposition-verb ADR's spend half is retired; its central argument stands, and is now load-bearing for a different predicate rather than for anything here.

07Alternatives considered

OptionWhy not
Keep it, stop investingThe preceding ADR's position, one day old. A frozen tier-4 control still costs false positives every session, still needs its two detectors, and still contradicts the charter. Freezing reduces the bleeding without addressing the diagnosis.
Fix it with a real shell parsershlex.split already raises on a live file here, and a third-party parser cannot go inside a stdlib-only script that must run on macOS 3.9. It would still be a tier-4 control fighting an unbounded space.
Keep the guard, drop only P15The cheapest option and genuinely tempting. Treats the noisiest symptom while leaving the mechanism the charter argues against.
Delete layers 2 and 3 as wellFirmly rejected. Layer 3 has never failed, and escalation is general infrastructure with nothing to do with this diagnosis.

08Re-evaluate when

  • A downstream actually runs unsupervised against real infrastructure → build layer 1 at tier 1, not tier 4. This is the trigger that should have gated the original build.
  • conclave adopts scoped credentials → the gap named above closes; record it.
  • An unauthorized provisioning event occurs that a text-matching guard would plausibly have caught by mistake rather than evasion → this decision is wrong and should be superseded on that evidence.
